# 精修逐字稿 Skill 使用说明

把一份口头禅多、断句乱、夹着识别错误的录音转写，整理成更好读的文字，同时保留说话人原来的意思。

你给 AI 一份原始转写，再让它按这个 Skill 处理，就能得到一份精修逐字稿。会议记录、课程录音的转写、访谈文字稿，都可以用。

第一次使用，先看下面的上手步骤。真正给 AI 使用的规则文件是 [SKILL.md](refining-transcripts/SKILL.md)。

## Skill 是什么

你可以把它理解成一份写给 AI 的工作说明。它告诉 AI 这项工作该怎么做，哪些地方可以改，遇到拿不准的信息该怎么处理。

这个包提供的是 Markdown 格式的 Skill 源文件，需要由 AI 工具读取并执行。它没有独立运行的应用程序，也没有内置语音识别引擎。

如果你手里只有录音，要先用能够转写音频的工具拿到文字，或者使用本身具备音频读取和转写能力的 AI。这个 Skill 接着负责整理转写。

## 它能帮你改哪些地方

它会处理明显的错别字和语音识别错误，补上标点，重新断句，把过碎的文字整理成自然段。没有实际意思的口头禅、连续机械重复，也可以清掉。

下面这句来自原始规范的演示。

> 对对对对，我我我也是这么觉得的。

精修后可以写成下面这样。

> 对，我也是这么觉得的。

但遇到这句，处理方式就不一样了。

> 我觉得他可能下个月会退出吧。

“可能”必须保留，不能写成“他下个月会退出”。同样，“要不下次试试”不能被写成“会议决定”。

遇到听不清的人名、拿不准的数字，它会标上“〔姓名待核〕”或“〔数字待核〕”，留给你核对。

## 哪些事需要另外交代

这套规则默认只整理逐字稿。会议纪要、行动项、课程总结和文章改写，需要另提要求，作为下一项工作处理。

有意义的追问、分歧和课堂互动应当保留。AI 不能为了让文字显得整齐，把这些内容删掉，也不能替讲者补上没说过的背景和结论。

这里的“精修”允许适度清理口头噪音。如果你需要每一个语气词、重复和停顿都完整保留，应另行说明记录标准。

## 第一次怎么用

### 在普通 AI 对话里使用

1. 打开 [SKILL.md](refining-transcripts/SKILL.md)，把完整内容复制到你使用的 AI 对话里。如果工具支持读取 Markdown 附件，也可以直接上传这个文件。不要只给它文件名。
2. 告诉 AI 这份文件是本次整理要用的规则。然后粘贴或上传原始转写，明确哪一份是待整理材料。
3. 发送下面这段话。完成后检查输出是否覆盖了整份材料，并核对“待核事项”。

```text
请按我提供的 refining-transcripts Skill，使用标准保真精修模式，
整理这份原始转写。

保留原意、说话人、已有时间戳和发言顺序。
只清理明显识别错误、无意义口头禅和机械重复。
无法确认的人名、术语、数字请标记待核。
只输出精修逐字稿；如有待核事项，附在文末。
不要额外生成会议总结或行动项。
```

只粘贴上面这段话，不能代替完整的 Skill 文件。换一个没有保留这些规则的新对话时，需要重新提供文件。

### 在支持 Skill 的工具里使用

取出本包中的 `refining-transcripts` 文件夹，按目标工具自己的 Skill 导入或安装说明放置。需要识别的入口文件是下面这个。

```text
refining-transcripts/
└── SKILL.md
```

文件夹名和文件名保持不变。整个分享包还带有说明与来源文件，导入时要选内层的 `refining-transcripts` 文件夹。

安装位置和触发方式由目标工具决定，本包没有自动安装脚本。导入后，可以先请 AI 确认是否已读取该 Skill，再给它一小段转写试用。

## 需要准备什么材料

最少准备一份原始转写。原文中如果有说话人标签、时间戳，尽量一起保留。

手里有参会名单、会议议程或专业术语表，也可以一起提供。这些资料能帮助核对名称，但不能证明某一句话一定是谁说的。

涉及客户资料、内部会议或私人信息时，先确认你有权把材料交给所用 AI 平台。不要把真实转写、账号配置或密钥上传到这个 Skill 仓库。

## 三种模式怎么选

| 你的需求 | 选用模式 | 主要区别 |
| --- | --- | --- |
| 整理会议或课程转写，方便阅读和回听 | 标准保真精修 | 默认模式，保留说话人和已有时间戳 |
| 特别在意人名、数字、职务是否准确 | 严格核校版 | 结合辅助资料核对，不能确认的明确标记 |
| 只想顺畅阅读，不太需要按时间回听 | 阅读优化版 | 需要明确提出，可合并碎句、减少时间戳 |

不确定选哪个，用默认模式即可。更多可复制的提问方式放在 [快速开始](docs/快速开始.md)。

## 最后会拿到什么

默认输出包含基本信息、精修说明和整理后的正文；有无法确认的信息时，文末会附上待核事项。内容导读可以有，但只用于查找章节，不替你总结观点。

AI 不一定每次都处理得完全准确。拿到结果后，重点检查姓名和数字，留意“可能”有没有变成“确定”、“建议”有没有变成“决定”。多人对话还要检查发言有没有归错人。

长材料要确认首尾都被处理了。如果当前工具一次读不完，可以按原始时间顺序分段，保留每段编号和时间信息，全部处理完再合并复核。不要把一部分输出当作全文。

## 文件怎么分工

| 文件 | 给谁看 | 用途 |
| --- | --- | --- |
| `README.md` | 第一次接触的同事或朋友 | 就是这份大白话说明 |
| `refining-transcripts/SKILL.md` | AI 工具 | 完整的执行规则 |
| `docs/快速开始.md` | 使用者 | 可复制的提问方式 |
| `examples/精修前后对照.md` | 使用者 | 看懂哪些能改、哪些不能改 |
| `source/通用Skill_精修逐字稿_迁移版_v1.0.docx` | 想查原始规范的人 | 保留的原始 Word |
| `source/来源与校验.md` | 维护者 | 来源、转换方式和验证范围 |

## 怎么发给同事或朋友

直接把本地的“精修逐字稿Skill_分享包_v1.0.zip”发给对方，让他解压后先看这份说明。只想先了解效果的人，可以先看 [精修前后对照](examples/精修前后对照.md)。

如果通过 GitHub 分享，以仓库当前可见性为准。私有仓库的链接只能给有访问权限的人使用；没有权限的朋友可以收压缩包。

本包依据原始迁移版 v1.0 整理。Skill 正文来自原文附录，保持原有规则；新增加的是使用说明和目录组织。没有附加新的开源许可证。
